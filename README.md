# «Князь» V3 — публичный сайт + админ-панель /admin

Цирюльня «Князь», Астрахань, пл. Свободы, 45. Публичная страница записи +
панель владельца на секретном URL `/admin` (ссылок с главной нет).
Серверная база данных (Postgres), серверная авторизация, записи — в базе,
а не в localStorage.

## Стек

- Чистый Node.js (ESM, без фреймворка) + `pg`. API — файлы `api/**/*.js`
  в стиле Vercel Serverless Functions (file-routing), та же статика
  (`index.html`, `assets/`) отдаётся с корня.
- Локальный dev-сервер — `server.js` (те же роуты, что на Vercel).
- Хранилище: Postgres при заданном `DATABASE_URL`, иначе файловый
  адаптер `data/dev.json` (только для локальной разработки/QA — данные
  не переживут деплой, в проде обязательно Postgres).
- Пароль владельца — scrypt (Node crypto), сессия — случайный токен,
  в БД только его sha256-хеш, cookie HttpOnly + SameSite=Lax (+ Secure на https).
- Защита от двойной записи — три рубежа: проверка слота в приложении,
  advisory lock по мастеру и EXCLUDE-констрейнт БД
  (`db/schema.sql`, ошибка 23P01 → 409 `SLOT_TAKEN`).
- Загрузка изображений — в БД (BYTEA), только JPG/PNG/WebP по magic bytes,
  до 3 МБ, случайное имя файла. Base64 в localStorage не используется.

## Быстрый старт (локально)

```bash
cp .env.example .env   # задать DATABASE_URL и SETUP_TOKEN
npm install
npm run seed           # применить схему + начальные данные (прайс V3, мастера-заглушки)
npm run dev            # http://localhost:3000
npm test               # smoke-тест (нужна СВЕЖАЯ база, см. test/smoke.mjs)
```

Без `DATABASE_URL` seed не нужен: файловое хранилище сидится само при
первом запуске.

Первая настройка: открыть `/admin/setup`, ввести одноразовый токен
`SETUP_TOKEN` из env, email и пароль (минимум 12 символов). После
создания владельца эндпоинт мёртв (403). Дальше вход — `/admin/login`.

## Структура

```
server.js            локальный dev-сервер (статика + API)
index.html           публичная страница (данные — из /api/public/config)
assets/              logo.jpg, hero.webp
admin/               панель владельца (SPA: index.html + admin.js + admin.css)
api/
  _lib/              http, validate, auth, slots, booking, store (+store-pg/store-file)
  setup.js           GET/POST /api/setup — первая настройка
  auth/              login, logout, me
  public/            config, slots, bookings (создание/отмена/перенос клиентом)
  media/[id].js      GET /api/media/:id — отдача изображения
  admin/             bookings, bookings/[num], services, groups, categories,
                     masters, media, settings, stats
db/
  schema.sql         DDL (включая EXCLUDE-констрейнт)
  seed-data.js       прайс V3, мастера-заглушки, настройки (источник правды для seed)
  seed.js            CLI: применить схему + seed
  legal.json         тексты политики и согласия (из V3)
test/smoke.mjs       сквозной тест: setup → вход → каталог → слоты → запись →
                     дубль 409 → гонка → цена → аватар → отмена → выход
```

Полный список эндпоинтов — в `API_CONTRACT.md`.

## Поведение, которое важно знать

- Псевдослучайная занятость слотов из V3 удалена: занятость считается
  только по реальным записям из БД + графику мастеров. Свободных слотов
  стало заметно больше — это корректно, а не баг.
- Цены в записи — снапшот на момент создания: смена цены в админке
  не меняет старые записи.
- Удалённые услуги/мастера — soft-delete: скрываются с сайта,
  старые записи сохраняются.
- Номера записей — из последовательности БД (`K-1001`, `K-1002`, ...).
- Часовой пояс салона — Europe/Samara (UTC+4), окно записи — 14 дней,
  слоты — каждые 30 минут, «сегодня» — не раньше «сейчас + 30 минут».
- Реквизиты ИП/ИНН/ОГРН — пустые поля в настройках, владелец заполняет сам.
  В политику подставляется примечание, пока они пусты (не выдуманы).
- Тексты политики (§6–§7) обновлены под серверное хранение: в V3 было
  написано «страница работает без сервера, запись хранится в браузере» —
  это больше неверно, в seed загружена исправленная редакция
  (остальные разделы — дословно из V3).

## Деплой (для DevOps)

- Vercel: проект со статикой из корня + Serverless Functions из `api/`
  (см. `vercel.json` — только rewrites для `/admin` SPA). Живой проект
  `knyaz-v3` не трогать до решения родителя.
- Env-переменные в Vercel (без значений в коде и репозитории):
  `DATABASE_URL` (Neon, ОТДЕЛЬНЫЙ проект от knyaz-barbershop, регион EU),
  `SETUP_TOKEN` (длинный случайный, удалить после настройки).
  Секрета подписи сессий нет: сессии — случайные токены, в БД только их хеш.
- После первого деплоя: `npm run seed` против prod-БД (или первый
  запрос к API сам применит схему и seed — `PgStore.init()`), затем
  `/admin/setup` с токеном.
- Файловый адаптер в проде не использовать: `DATABASE_URL` обязателен.
